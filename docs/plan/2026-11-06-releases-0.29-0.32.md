## 0.29.0
- **FR-055 Slot edit by content.** The edit form matched lines to slots by line number, so inserting a line renamed every slot below it while the players stayed in their rows. Now a line equal to an existing slot's role, weapon and duty keeps that slot; leftover lines become new empty slots; leftover empty slots are renamed or removed; a held slot with no matching line gives the existing "someone holds it" error. Positions are still numbered by role (ADR 0030): a new Healer renumbers the rows below it, and each player keeps their own slot.
- **FR-056 Manage panel in place.** Lock, Unlock, End, Cancel and Reopen update the panel message itself (Lock turns into Unlock, one status line), with no second message.
- **Duties**: Party Healer 💚 and Main Healer 💖.
- **FR-062 Calendar readability.** No emoji in event titles; the title is a `###` heading and the metadata line is normal-size text (it was `-#` subtext). Fewer events fit a message, so the split is recalculated.
- **FR-023 Categories.** PvE: add Static dungeon, Dragon sanctuary, Hellgate, Depths, Avalonian raid, Crystal creatures, Ancient Lands; remove Fame farming and Avalonian gold chest. PvP: add Outposts, Castle, Ancient Lands. A category in both types shares one ID, as Other does. Removed IDs stay readable for old content and are hidden from the menus.
- **FR-061 Changelogs.** `changelog/<version>.md` per release (plain-language summary plus "how to use it"); a changelog channel option in `/content setup`; `scripts/post-changelog.ts` with `--dry-run`, run in Docker at release.

## 0.30.0
- **FR-057 Fill preferences.** A fill chooses Any, roles, or specific positions (one multi-select in a private panel; Any first, then roles, then positions, 25 options at most). Choices are stored as slot IDs and role names. The bot seats the player in the first open position that matches; Any prefers Healer, then Tank, DTank, Support, DPS. With no match the player waits as a fill, shown as `fill (Healer, #7)`, and the first waiting player a freed position fits is seated, in join order, through the waitlist promotion. Every fill seating posts in the thread, mentioning only that player: `🔁 @Player joined as fill (Healer, #7) and was seated in position 3 · Healer – Holy Staff.` A waiting player may choose Fill. Reserved seats and Assign fill are removed; the host moves players with Manage. A migration seats current fills where a position fits and turns the rest into waiting fills (Any).
- **FR-058 Selection mode.** A toggle on the creation card and in the Edit panel. The post carries the line "Selection event: signing up is an application. The host picks the party." Signing up (a position, or fill with the same targets) is an application and holds no seat; several people may apply for one position. The roster has an Applicants section. Manage gets **Review applicants** (built like Add player): Accept seats the player through the assign logic (the host picks another position if it is taken); Decline removes the application. Each outcome mentions the applicant in the thread; the applicant gets a private confirmation when applying. Turning the toggle off with applicants asks the host to review them first.

## 0.31.0
- **FR-059 Creation hub.** The calendar channel is renamed content-management and its first message carries two buttons: **Normal content** and **Special content (CTA)**. CTA is limited to the roles set with a new `cta-roles` setup option (admins always allowed). Each button opens the creation card. Normal content posts to the event forum of its type; CTA posts to the CTA channel (new `cta-channel` setup option). The launcher post and `/content create` are removed.
- **Calendar groups (owner, 2026-11-06).** The calendar separates CTA content from normal content. Under each day, CTA events come first in a "📣 Call to arms" group and normal events follow in a "Content" group; events already running keep the same split. A day with only one kind shows only that group. This needs content to carry a CTA flag (in the 0.31.0 migration); until then every event is normal content.
- **FR-060 Blank content.** Offered in both flows. It skips the card and opens the final form with Title, Start (UTC), Gear tier and Description. A normal blank first asks for PvP or PvE in one menu (to choose the forum). It is announced like other content (bot-made post, calendar entry without a party count) but has no roster: no sign-up, Leave, loot vote, Ping or attendance. Manage offers Edit, Lock, End and Cancel.
