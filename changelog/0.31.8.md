# 📣 What's new in 0.31.8

## ⚔️ Two parties in one CTA
A CTA can now have **two parties**, each up to 20 players. Each party gets its own roster message in the CTA thread, with its own positions, Fill and waitlist.

**For CTA hosts: how to make one**
1. Press **Schedule CTA** in the content-management channel. The CTA card no longer asks for a Type or Category.
2. In **Parties**, choose **2 parties**.
3. Press **Details** and write party 1's positions, one per line, like `Healer - Hallowfall`.
4. Press **Party 2 slots** and write party 2's positions, or press **Copy party 1** if both parties are the same.
5. Press **Create**.

Slot roles for a CTA are **Tank, DTank, Healer, Support** and **DPS**. If you type another role, the card tells you which line to fix.

**For players**
- Pick a position in the party you want. Picking a position in the other party moves you there.
- **Fill**, **Tentative**, **Leave** and the waitlist work inside the party whose message you used.
- Each party counts from 1.

**For hosts after creating**
- **Manage** is on Party 1's message. Assign, Add, Remove, Set weapon, Duty, Review applicants and Attendance first ask which party.
- Attendance is marked per party. The report is posted once both parties are done.

## 🏷️ CTA names match event posts
The CTA thread and its announcement are now named like event posts, for example `Raid | 12 Nov | 20:00 UTC`. The announcement has a **Roster** button that takes you straight to the roster. Both update when the host changes the title or the start.
